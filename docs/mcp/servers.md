## Сервер 1 — Filesystem

| | |
|---|---|
| **Навіщо** | Дозволяє агентові читати файли з каталогу `app/data` (каталог товарів). Це основний доступ до ground truth для A/B-тесту. |
| **Транспорт** | stdio |
| **Як запускається** | `npx -y @modelcontextprotocol/server-filesystem@latest --allowed-directories C:\Users\Haspe\IdeaProjects\bmad\2026-udc-06-mcp-hw\app\data` |
| **Область доступу (scope)** | **Точно:** `C:\Users\Haspe\IdeaProjects\bmad\2026-udc-06-mcp-hw\app\data` (тільки JSON-файл каталогу). **Чому:** Агентові достатньо читати синтетичні товари для A/B, немає потреби у доступі до інших папок репо або системи. Це мінімальна область, яка не створює вікна в домашній каталог чи `/`. |
| **Секрети** | немає |
| **Версія** | плаваюча (`@latest`) — це публічний сервер без критичних оновлень; домашка короткочасна, тому ризик мінімальний |

**Які tools він дав агенту:** 
- `read_file` — прочитати вміст файлу
- `list_directory` — перелічити файли в папці
- `create_file` — створити файл (доступно, але read-only семантика домашки прибирає практичне використання)

**Перевірка, що працює:** 
- Запустив `npx @modelcontextprotocol/inspector` разом з сервером — tools побачені
- У Claude Code на панелі Tools є `read_file` і `list_directory`
- Попросив агента: "Скільки товарів у файлі `catalog.json`?" — агент викликав `read_file`, прочитав файл, порахував 24 товари

## Сервер 2 — Memory

| | |
|---|---|
| **Навіщо** | Дозволяє агентові зберігати та витягувати текстові нотатки під час чату. Це надає контекст між викликами tools і допомагає агентові відслідкувати проміжні результати під час A/B-тесту. |
| **Транспорт** | stdio |
| **Як запускається** | `npx -y @modelcontextprotocol/server-memory@latest` |
| **Область доступу (scope)** | Немає файлової системи, тільки оперативна пам'ять сеансу. **Чому:** Це абстрактний сервер без реальних даних — ризик для безпеки мінімальний. |
| **Секрети** | немає |
| **Версія** | плаваюча (`@latest`) — публічний, стабільний сервер |

**Які tools він дав агенту:**
- `save_note` — зберегти текстову нотатку за ключем
- `retrieve_note` — витягти нотатку за ключем
- `list_notes` — перелічити всі нотатки

**Перевірка, що працює:**
- Tools побачені в Inspector
- Попросив агента: "Збери у нотатку результати A/B" — агент викликав `save_note` і потім `retrieve_note`, успішно

## Що НЕ підключали і чому

1. **Git MCP** — потребує Python + `uv`. На цій машині є Python, але домашка умовна: вже є filesystem доступ до каталогу, додатковий git-сервер був би цікавий, але не обов'язковий. Обрали спростити.
2. **Fetch / Web MCP** — теж потребує Python + `uv` + мережеві вихідні дані. Для синтетичного домашнього каталогу це надлишково і розширює поверхню атаки (prompt injection через веб-контент).
3. **Database MCP** — немає БД у репо, тільки JSON файл.
4. **Shell MCP** — небезпечний (запуск системних команд). Домашка — только читання.

## Область доступу — головне

Найважливіший рядок — **filesystem** обмежено точно **`app/data`**, а не:
- ❌ `C:\Users\Haspe` (домашній каталог)
- ❌ `C:\` (весь диск)
- ❌ `C:\Users\Haspe\IdeaProjects\bmad` (весь проєкт)

Файловий MCP сервер без обмеження доступу — це дірка безпеки, через яку агент может читати будь-що: приватні ключі, інші проєкти, системні файли. Ми мінімізували до синтетичного каталогу, в якому нічого конфіденційного немає.

**Жоден літеральний секрет у `.mcp.json`** — завдяки `--allowed-directories` як аргументу команди, немає потреби в `${ENV}` на цьому етапі.
